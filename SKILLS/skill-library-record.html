01What a skill is here

The handbook says what each agent is. A skill says what it actually does at one moment, and what it must never do at that moment.

AGENT_HANDBOOK_24.md is the source of truth for the roster: 24 agents across Command, Revenue, Marketing, Operations and People, composing into 18 sellable hires. It gives each agent a job description, responsibilities, an autonomy level, KPIs, and — for eleven of them — a hard boundary, a named action the agent must never take regardless of instruction.

Skills decompose that into operable units. One skill is one triggerable behaviour: quiet-hours-clock, two-slot-closer, money-movement-interlock. The catalogue in agent-skills-24.html names all 187 and flags which carry an interlock.

The design constraint that shapes everything below: a skill has to be safe to read alone. An agent invoking one skill may never see the other six. So every skill restates its agent's absolute rules in full rather than referring to them — the redundancy is deliberate, and it is why the files total 126,000 words.

02The authoring contract

Every file obeys the same shape, so a reader and a validator can both find any part of it without searching.

Eleven boundaries, twelve interlocks

Each handbook hard boundary became a dedicated skill whose only job is to hold that line. VOX carries two — immediate human transfer on request, and jurisdictional recording consent — because its single handbook boundary line covers both obligations, and they fail in different ways.

One syntax rule worth recording

Agent directory names contain parentheses, which break Markdown link syntax whether escaped or percent-encoded. So same-agent links are relative ([`name`](../name/SKILL.md)) and cross-agent references are backticked plain text, never linked. Every cross-agent reference in the set is therefore a token a script can resolve, which is what made the audit mechanisable.

04How they were written

Generated from a parsed catalogue against per-agent scaffolds, then validated structurally — never hand-typed one at a time.

01

Parse the catalogue

Extract all 187 name/description pairs and interlock flags from agent-skills-24.html by regex, and reconcile the counts per agent before writing anything.

02

Lift the inherited blocks verbatim

Each agent's §5 Hard Rules come from its own AGENTS.md, copied exactly rather than paraphrased, so the restatement in every skill is identical to its source.

03

Design the conflicts before writing

Known collisions were resolved at authoring time and written into both sides — ECHO's sixty-second reply against AEGIS quiet hours, EMBER's 21-day guard against TEMPO's no-show recovery, HONE's scoring against VOX's recording consent.

04

Emit through a generator

A per-agent scaffold writes the six-section body from a skill dictionary, so section order, heading text and the two-group hard-rules structure cannot drift between files.

05

Validate structurally

Directory name equals frontmatter name; six sections present, ordered, non-duplicated; contiguous procedure numbering; both hard-rule markers present exactly once; every relative link resolves; no parentheses in any link target.

Every edit after generation ran as a checked script — (path, old, new, expected_count) — printing MISS and skipping rather than writing when a count did not match. Across the audit that discipline caught zero silent failures in 60 applied edits, which is the only reason the counts in this document can be trusted.

05The audit

Structural validation proves every file has the right shape. It says nothing about whether two correctly-shaped files contradict each other.

The audit ran at three levels — within each agent, across agents inside a department, then across all five — followed by a fourth pass that walked complete journeys end to end. Each level used a different instrument, because each finds a different defect.

Level 1 · within an agent — 0 findings

All 187 Specific to this skill rule sets were dumped and read against their siblings. No agent contradicted itself. The two that once did — CIRCUIT's builder implying it activates against "backtest is the only activator", LEDGER having no behaviour for a calibration VANTAGE withheld — had been fixed in an earlier pass.

Level 2 · within a department — 1 finding

Skills written in the same sitting agree with each other. The single find was ABACUS against WARDEN inside Operations.

Level 3 · across departments — 9 findings

This is where conflicts concentrate, and the reason is structural: no one was reading both files at once. Two agents granted themselves exemptions from a clock a third owns. The cost ledger acquired two named owners. Lead-source spend was attributed to an agent that meters tokens.

Level 4 · end-to-end path walks — 5 findings

Six real journeys were traced hop by hop — lead to close to retention, stop-signal propagation, content to send, recruit to productive, close to paid, automation build to retirement. At each seam the check is one-sided delivery: does the sender name its receiver, and does the receiver fire on that sender?

Most serious finding

Six agents were required to escalate compliance findings to AEGIS, and no AEGIS skill fired on one. PULSE's disposition pattern, HONE's team gap, HONE's producer conduct pattern, CIRCUIT's proposed field, VANTAGE's geographic finding, HARBOR's candidate-set skew.

What made it more than a missing wire: every one of those agents is explicitly forbidden to adjudicate its own finding. HONE detects and never adjudicates; PULSE escalates rather than explaining away; VANTAGE surfaces but never plans the entry. So a fair-lending pattern could be detected, reported, and never determined — sitting open with no owner, the detection on the record and the silence after it on the record too.

It was traced to the source: AGENT_HANDBOOK_24.md specifies HONE as escalating to AEGIS, while AEGIS's own eight responsibilities were all outbound inspection and its own scheduled work. The skills had faithfully inherited a one-sided edge from the handbook.

Why the ownership sweep is the one that matters

Reading rules against rules finds contradictions. It cannot find an absence — a declared input with no producer, a shared counter with two owners or none, an escalation with no receiver. No amount of reading the rules that exist will surface a rule that does not. That is why the machine traces came first: 68 declared cross-agent producer/consumer edges and 16 declared agent-to-agent deliveries, each checked for its other half.

06Findings register

Fifteen conflicts, all fixed on both sides of the edge rather than patched at the consumer.

L3

Two agents exempted themselves from a clock AEGIS owns

AEGIS's quiet-hours-clock named the opt-out confirmation as the single exemption. ECHO claimed replies to inbound messages aren't silenced; BEACON claimed a broadcast post has no contact clock. Both are right — neither existed in the authority. Now stated in AEGIS as one carve-out (who spoke first) and one scope limit (no recipient).

L3

Permanent exit state had a writer, five readers, and no owner

ECHO wrote exits "to the consent ledger"; AEGIS's consent-ledger never mentioned exits, didn't fire on one, and didn't list it as a state it held. PULSE, EMBER, FORGE, TEMPO and VOX all read it from there.

L4

Escalation path to AEGIS terminated nowhere

Six agents escalating; no receiver, no adjudication, no return path. Fixed in the skills and in the handbook. See above.

L3

The cost ledger had two named owners

ABACUS's meter declares itself the single cost ledger, but RELAY and BEACON drew cost from "ATLAS's ledger" in five places — an earlier correction that never propagated to Marketing.

L3

Lead-source spend attributed to an agent that doesn't hold it

Four skills pointed at ABACUS for per-source and paid-lead spend. ABACUS meters tokens and voice minutes; LEDGER holds spend by channel. HARBOR's cost-per-placement was reading a job-board invoice out of a token meter.

L3

The frequency cap had two owners and neither named the other

AEGIS holds the ceiling, RELAY holds the cross-agent touch count. Now split explicitly on both sides, on the pattern already used for the ABACUS/ATLAS budget split.

L3

The voicemail counter and the touch count ignored each other

VOX owns one drop per contact per day across all agents; RELAY owns the total touch count. Both now state that two rules apply and neither assumes the other enforces.

L3

HARBOR asserted a WARDEN acceptance WARDEN never emitted

HARBOR's onboarding requires catching "a provisioning request WARDEN did not accept". WARDEN's day-one-provisioner had no HARBOR trigger and returned no acceptance.

L2

ABACUS needed a dependency list WARDEN only produced after the decision

ABACUS's downgrade recommendation must carry what a downgrade would break. WARDEN enumerated dependencies on the entitlement change — after the customer already decided.

L3

A candidate earnings case ran on plan rules that compute nothing unconfirmed

TALLY: "a plan the producer has not confirmed does not compute anything real." A candidate has confirmed nothing. HARBOR's case now names the published standard plan and states it is never the terms on offer.

L3

A transactional carve-out three departments cite as a rule was only a procedure step

TEMPO, FORGE and VAULT all cite RELAY as naming transactional sends as the ones that never yield. It existed — as step 4, not a hard rule. Promoted rather than added.

L4

A spam complaint had no door into the consent ledger

RELAY's rule says a complaint is a consent signal, not a deliverability statistic. AEGIS's trigger list was keyword, reply, call request, form, or human-relayed request — a carrier feedback-loop complaint is none of those.

L4

QUILL and CANVAS escalate refusals to ATLAS, which had no receiver

Added to signal-router, with a rule that ATLAS routes the named problem to whoever can change the facts and never re-shops the request to a different agent.

L4

An EMBER referral was not a lead SCOUT fired on

source-normalizer fired on "any connected source" — an internally handed-over referral is not one, and it arrives with no consent of its own.

L4

WARDEN fired on "a plan change from ABACUS"

ABACUS's hard rule is that it never changes a plan — it is L1 advisory and the customer authorizes. Retriggered on the authorized change instead.

07What the method actually taught

  • The serious findings are absences. Every one of the worst four was something missing, not something wrong. Text-versus-text reading found none of them.
  • Conflicts concentrate at the department boundary. Zero within an agent, one within a department, fourteen across. Files written together agree; the seam is where nobody was reading both sides.
  • A one-sided edge is the diagnostic shape. Sender names a receiver that never fires, or a receiver fires on a sender that emits nothing. Both halves declared is the passing condition.
  • Check the convention before calling a defect. The set declares inbound edges when it means them — AEGIS's ledger names ATLAS's router as its source. That convention is what made six missing declarations a real deviation rather than a modelling assumption.
  • Trace a claim to the source of truth. The AEGIS gap looked like a drafting slip in the skills until the handbook showed the same asymmetry. Fixing only the skills would have left the defect regenerating.
  • Not every flag is a break. A gate that fires on all outbound should not enumerate its callers; a broadcast producer should not list its readers. Those were checked individually and left alone.

08Open

  • Handbook conformance for the other 23 agents. One agent's skills have been checked against its handbook entry, and that check found a real defect on the first try. The remaining 23 are unaudited against the source of truth — and it is the one check whose misses are invisible to every other check.
  • The 18 hire compositions. A hire such as "The ISA" composes SCOUT, PULSE, ECHO and TEMPO into one sellable unit. Whether each composition has an unbroken end-to-end process is a level above where this audit worked.
  • Stale roster counts in the HTML. agent-roster.html says AEGIS is "the reason the other nineteen can be trusted" and tests "against the other nineteen". The handbook says twenty-three. Predates this work; likely present in sibling files too.
  • Nine validator warnings, deliberately unfixed. Five Command skills carry three specific bullets against a four-bullet threshold; four Marketing skills use prose triggers rather than bullets. Spot-checked and intentional — CANVAS's pre-publication review uses prose precisely to say "Runs on 100% of assets — a sampled review is the same as no gate." Padding them to satisfy a threshold would make them worse.
